## Summary

Step 5 of the wizard shows three commands, offers Copy, and writes them into
`run_finetune.sh` and `run_finetune.ps1`. `frontend/README.md` §4.4 calls
them "the exact commands". Compared with the repository on 2026-11-14:

| Generated (`VoiceStudio.cpp:435-446`) | Repository |
|---|---|
| `python_training/prepare_target_voice.py --voice … --takes … --room-tone … --out … --holdout-minutes 5` | **The script does not exist.** `python_training/` has no `prepare_target_voice.py` |
| `train_unit_vocoder.py --fine-tune --speaker … --data … --base-bundle … --out …` | None of these five options exists. The parser requires `--train-manifest` and `--train-units` and offers `--finetune-from`, `--run-name`, `--ckpt-dir` (`train_unit_vocoder.py:716-756`) |
| `export_stateful_onnx.py --role vocoder --checkpoint … --bundle … --license "…"` | Options exist (`export_stateful_onnx.py:70-76`). Not checked further |

A second problem affects the PowerShell file only. Each line starts with a
quoted path (`'C:\…\python.exe' 'C:\…\script.py' --voice …`). In PowerShell a
leading quoted string is an expression, not a command; it needs the call
operator `&`. The script stops with a parse error before running anything.
`$ErrorActionPreference = 'Stop'` also does not stop the script when a native
program returns a non-zero exit code, so a failed step would not prevent the
next one. (PowerShell behaviour stated from knowledge of the language; not
executed.)

## Expected

Either the commands run against the scripts in the repository, or the step
says plainly that the fine-tune tooling is not available yet.

## Root cause

The Studio was written against the M2 Stage 10 *plan*. Stage 10 has not been
implemented, so the command line it describes never existed. No test compares
the generated commands with the real argument parsers: the existing checks
look for substrings only (`tests/test_frontend_model.cpp:573-589`).

## Suggested fix

1. Until M2 Stage 10 lands: label step 5 "Planned commands (fine-tune tooling
   not available in this build)", disable "Write job", and keep the draft and
   the take analysis, which are useful on their own.
2. When Stage 10 lands: generate the commands from one description shared
   with the Python side. A small `python_training/studio_job.py --from job.json`
   entry point that reads the manifest the Studio already writes is more
   robust than assembling three command lines in C++.
3. PowerShell: prefix each line with `& `, and after each line add
   `if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }`.
4. Reject a voice name that starts with `-` in `name_problem()` (it would be
   parsed as an option).

## Regression tests

- A CTest case that extracts the option names from the generated commands and
  checks each against `--help` of the corresponding script (stdlib Python,
  no torch import needed if the parsers are importable without it; otherwise
  a checked-in list of options regenerated by a pytest).
- A parser-level check of the generated `.ps1` and `.sh` text: every command
  line of the `.ps1` starts with `& `.

## Workaround

None. The fine-tune must be run by hand with the real options of
`train_unit_vocoder.py` once the preprocessing script exists.
