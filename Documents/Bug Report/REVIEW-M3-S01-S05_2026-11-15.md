End-to-end code, specification, build, and test validation of **Milestone 3 Stages 01 through 05** on `2026-11-15` (Stage 01–02 committed in `4f6d225` and earlier; Stages 03, 04, and 05 in the working tree).

Six defects were found, reproduced empirically, and filed as:
- **[BUG-027](BUG-027_s2ut_data_prep_archive_plumbing_broken.md)** (*Broken archive plumbing* — `prepare_s2ut_data.py` cannot download or extract S2UT corpora as documented; High)
- **[BUG-028](BUG-028_fifo_strands_partial_eos_chunk_frames.md)** (*Stranded tail frames* — `UnitProsodyFifo` + `s4` vocoder drops the final 1–3 frames at `<EOS>` and leaks them into the next utterance; High)
- **[BUG-029](BUG-029_ctc_adaptive_probability_never_catches_up.md)** (*Half-wired readiness* — Stage 04 widened readiness to `[0, 2]`, but Stage 05 `translator.py` / `s2ut_stream.py` still clamps and feeds `(0, 1)` probabilities, yielding 0 two-write catch-up steps; Medium–High)
- **[BUG-030](BUG-030_silence_tail_babble_passes_gate_and_eval.md)** (*Blind tail audit* — a non-terminating babbling decoder scores `flush_tail_chunks = 0` (`PASS`) and `hallucinated_words = 0` in `gate_s2ut.py`, while `silence_hallucination_20.tsv` has English `tgt_text` for `es`/`fr`/`de` targets; Medium–High)
- **[BUG-031](BUG-031_s2ut_pipeline_drops_noncommercial_taint.md)** (*Laundered non-commercial taint* — `units.audio_rows`, `train_s2ut.py`, and `export_step_graphs` drop `noncommercial: true` from VoxPopuli manifests and NC-trained S2UT checkpoints, exporting them as `"MIT"`; Medium)
- **[BUG-032](BUG-032_cpp_voice_catalog_ignores_voice_lang_field.md)** (*Dropped voice language* — C++ `VoiceCatalog` parsers accept ill-typed `"lang"` in `voices.json` and discard per-voice language metadata; Medium)

**Overall verdict: Stage 02 (`ModelContract` v2 & ONNX fixtures) and the core math of Stage 03 (dual-output causal student + restricted fairseq loader + balanced k-means), Stage 04 (`WaitKPolicy` C++/Python bit-exact state machine), and Stage 05 (ring-KV causal Conformer-Transformer `step() == forward()` over 60 s) are well-engineered and pass all unit/parity suites. However, BUG-027..BUG-031 must be fixed before launching external data preparation, GPU training, or the Stage 05 decision gate, and BUG-028 + BUG-032 must be resolved before Stage 07/08 C++ Mode B integration.**

## 2. Additional findings & test gaps (non-bug / design risks)

Ordered by impact on the upcoming GPU training and Stage 07/08 C++ integration:

1. **F-1 · `train_s2ut.py::validate()` is not stratified across the 6 translation directions (Medium).**
   `train_s2ut.py:325-340` evaluates `dataset[0 : min(limit, len(dataset))]` (`--val-limit 200` by default), where `join_items()` preserves `--manifest` file order. On real corpora (`s2ut/cvss-c-es_en.jsonl` has > 13,000 `dev` rows), the first 200 items are **100% `es->en`** — so `best.pt` (`v["k3"]["unit_acc"] > best`, `line 518`) is selected on a single language pair while `fr->en`, `de->en`, `en->es`, `en->fr`, and `en->de` are never validated. Stratify evenly across all 6 directions (matching `train_content_encoder.py::select_val` and `train_unit_vocoder.py::select_val_items`) and log per-direction `unit_acc`.

2. **F-2 · Teacher-forced `[EOS/PAD] -> [PAD, eos=1]` creates an absorbing mute state when `<EOS>` fires before a flush reset (Medium, Stage 05/08 hazard).**
   In `translator.py::build_targets()` (`lines 713-721`), every silence-tail or early-finishing training example supervises `prev_units` containing `<EOS>` or `<PAD>` to emit `[PAD, PAD, PAD, PAD]` and `eos = 1`. At run time (`s2ut_stream.py:320`), `self.prev_units` is updated unconditionally to the raw decoder output `[..., EOS, PAD]`. If `<EOS>` fires while `speech == True` (`WaitKPolicy` ignores `<EOS>` while speaking) or during a `< 400 ms` breath pause followed by resumed speech (`05_causal_s2ut_translator_policy_gate.md:200-203`), the translator state is *not* reset, so feeding `prev_units = [..., EOS, PAD]` trains the decoder to stay stuck emitting `<PAD>` until a `> 400 ms` silence finally triggers a full reset. Either hold `prev_units` / reset decoder state after `<EOS>` + speech resumption, or include multi-utterance concatenated examples in `S2utDataset`.

3. **F-3 · `gate_s2ut.py::convert_utterance()` runs Stage 1 `frontend.latents(chunk)` unconditionally during `IDLE` and `kFlush` (Low–Medium).**
   In `gate_s2ut.py:515-518`, `frontend.latents(chunk)` executes on every 80 ms chunk before checking `translator.policy.source_wanted()`. During leading silence, `noise_only` clips, and `kFlush` steps (`source_wanted() == False`), Stage 1's ONNX encoder runs and its `latents` are immediately discarded (`s2ut_stream.py:355`). While `write_ms` filters on `s["encoded"]` (`line 540`, so `kFlush` steps do not skew `write_ms`), `timing.csv` (`rtf`) includes the wasted Stage 1 calls on silent tail padding.

4. **F-4 · Combined Stage 1 + Stage 2 + Stage 3 single-core FP32 CPU compute exceeds the 40 ms gate ceiling on the development laptop (Medium, schedule risk).**
   Stage 03 measured `encoder_s4 + vocoder_s4` ORT `p95` at `29.2–35.3 ms`, and Stage 05 measured `translator_enc + translator_dec` WRITE ORT `p95` at `23.2 ms` (`~52–58 ms` combined vs. the `<= 40.0 ms` Stage 05 eligibility rule). Even accounting for background host load during those smoke runs, streaming 105 MB of FP32 translator weights + causal convs on one CPU core leaves almost zero margin at `d_model = 320, 6+6 layers`. Re-benchmark on an idle machine in C++ (`OrtModel` with `IoBinding`) before committing multi-day GPU training at `6+6 × 320`, so `d_model = 256` or `4+4` layers can be added as a candidate if FP32 CPU `p95 > 40 ms`.

5. **F-5 · Smaller hygiene & edge-case items (Low):**
   - `python -I python_training/make_waitk_golden.py --check` from the repo root fails with `ModuleNotFoundError: No module named 'fvml'` because `make_waitk_golden.py` lacks the `sys.path.insert(0, str(Path(__file__).resolve().parent))` guard present in `gate_s2ut.py`, `test_contract.py`, and `export_stateful_onnx.py`.
   - `extract_units.py` (`line 576`), `train_content_encoder.py` (`line 497`), and `make_s2ut_eval_lists.py` (`line 261`) do not reconfigure both `sys.stdout` and `sys.stderr` to `encoding="utf-8", errors="replace"` (`BEST_PRACTICES.md` §4.7).
   - `extract_units.py:339` writes `meta["prosody"]` to `units_meta.json` before iterating `todo = rows[:args.limit]`; running `--prosody --limit N` on an existing units directory marks the whole directory as having prosody while leaving the remaining rows without `.prosody.npy`.
   - `train_s2ut.py` overwrites `history.json` on `--resume` instead of preserving prior steps (`line 530`), and both `train_s2ut.py` and `train_content_encoder.py` lack `train_unit_vocoder.py`'s non-finite (`NaN`/`Inf`) loss/grad guard.
   - `translator.py::_ctc_term()` (`lines 795-800`): if a manifest row has non-empty punctuation-only `src_text`/`tgt_text` (e.g. `"..."`), `join_items()` accepts it (`bool("...") == True`) while `asr.normalize_multilingual("...")` yields `""` (`lengths == 0` in `F.ctc_loss`); filter `join_items()` on normalized non-empty token sequences.
   - `.github/workflows/build.yml` (`python-m2-contract` job, `lines 128-131`) runs `test_contract.py`, `test_fixtures.py`, `test_prepare_s2ut_data.py`, `test_eval_s2ut.py`, and `test_waitk_policy.py`, but does **not** run `gate_s2ut.py --self-test` or `make_waitk_golden.py --check` (the C++ CTest step runs `gate_s2ut_selftest`, which is skipped whenever a native C++ build fails as on `windows-msvc`).
