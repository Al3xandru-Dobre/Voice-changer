# Review — Milestone 2 Stage 05: causal vocoder & decision gate (2026-10-18)

> [Bug index](00_index.md) · Stage: [05 causal vocoder & decision gate](../Milestone%202/05_causal_vocoder_decision_gate.md) · Previous reviews: [M2 S01–S02](REVIEW-M2-S01-S02_2026-10-18.md) · [M1.5 S05–S06](REVIEW-M15-S05-S06_2026-10-18.md) · [M2 S06](REVIEW-M2-S06_2026-10-18.md)

Implementation review of the Stage 05 work in the tree on 2026-10-18 (all
uncommitted): `python_training/fvml/vocoder.py`, the transposed-convolution
addition to `fvml/streaming.py`, `train_unit_vocoder.py`, `gate_report.py`,
the `--role vocoder` mode of `stream_check.py`, `--cost-vocoder` in
`probe_units.py`, `tests/test_vocoder.py`, and the `python_training_stage05`
CTest entry. Defects are filed as
[BUG-015](BUG-015_gate_decides_on_pytorch_clock.md),
[BUG-016](BUG-016_gate_export_silent_exporter_fallback.md) and
[BUG-017](BUG-017_vocoder_checks_below_noise_floor.md); this file holds
everything that is not a single defect.

**Result.** The generator, the streaming transposed convolution and the losses
are sound: I re-derived the transposed-conv context/trim arithmetic, measured
the receptive field empirically, and found no causality or state-plumbing
defect in the model. The problems are in the **decision gate** (it decides on the
wrong clock, can pass on the wrong exporter, and exits 1 on success under a
cp1252 console), in **verification that cannot fail** at the amplitude it runs
at, and in a **test suite that leaves most of the training and gate logic
unpinned** (28 of 41 deliberately broken variants survived). The stage file is
honest that the 150k-step runs are pending; two of its recorded figures are
wrong or not reproducible (§5).

## 3. What I verified is correct

- **Transposed-conv causality.** For kernel k, stride s the code prepends
  `context = (k−1)//s` input frames, runs `conv_transpose1d`, drops
  `context·s` samples on the left and `trim_right = k−s` on the right. Output
  window [t·s, (t+1)·s) then depends on input frames t−context … t only. I
  checked all four generator stages (k/s = 16/8, 10/5, 8/4, 4/2 → context 1,
  trim 8, 5, 4, 2) and the whole model by perturbation: changing frame 0 changes
  output up to sample 9 491 (593 ms) and nothing after, consistent with the
  606 ms the code reports. No lookahead anywhere.
- **FiLM** is identity-centred and per-channel, so it is linear in `spk_emb`;
  `test_film_blend_and_expand_speakers` pins the 50/50 blend identity that
  Stage 09's timbre control needs.
- **Gate arithmetic.** `projected_t_minus_b_ms` = 25 + hop + L·20 + p95 + 5
  reproduces every projected value in the stage table (65.4, 86.7, 106.5, 108.7;
  54.5, 74.9, 94.6, 98.2) and the master plan's budget constants.
- **Alignment of lookahead heads.** Encoder head L emits frame t−L at step t,
  and `PitchTracker(lookahead_frames=L)` emits t−L too, so units and
  conditioning arrive aligned; `best_lag` (±200 ms) absorbs the L·20 ms delay in
  the F0-PCC metric.
- **Checkpoints** carry config, contract JSON, voices, speakers, stats, RNG
  state; `weights_only=True` loading works; `save_checkpoint` validates the
  voices before writing, which incidentally prevents a NaN-weight checkpoint
  from overwriting a good one.
- **Licences/attribution** for LJSpeech (public domain) and the four Hi-Fi TTS
  readers (CC BY 4.0, attribution strings) are in `SPEAKER_METADATA` and flow
  to `voices.json`.
- **Throughput.** Feature extraction cost 18 ms per training sample (measured on
  the loaded machine), so two workers can feed ≈ 7 it/s against the 2.72 it/s
  the stage file reports for the GPU: the loader should not be the bottleneck.

## 4. Findings that are not single defects

Ordered by what I would act on first.

**F-1 · Mutation testing: 28 of 41 broken variants survive (Medium).**
Method as in the S01–S02 review: one rule broken at a time in a scratch copy,
full `test_vocoder.py` + `test_streaming.py` run with `-x`.

| Area | Killed | Survived (rule that nothing pins) |
|---|---|---|
| Streaming caches | transposed-conv cache dropped; conv1d cache dropped when dilation > 1; cache off-by-one | — (but only by the *layer* tests; BUG-017) |
| Generator wiring | speaker row ignored; FiLM γ not identity-centred | **FiLM bypassed entirely**; FiLM β dropped; **voicing channel zeroed**; **energy ↔ aperiodicity swapped**; **ResBlock dilation ignored (receptive field silently shrinks)**; MRF average removed; output `tanh` removed; unit repeat `tile` instead of `interleave` (Mimi only) |
| Losses / discriminators | D step on non-detached fake; mel clamp floor | **LSGAN real target 0 instead of 1**; MRD magnitude from real part only; mel weight 45 → 0 |
| `voices.json` | — | **embedding taken from row 0 for every speaker**; `logf0_std` filled from `energy_std` |
| Trainer | targets exclusion; `speakers_order`; `expand_speakers` init row | per-speaker stats (E[x²] sign error; energy over voiced only); crop offset not scaled by `unit_repeat` (Mimi only); causal pre-roll removed; LR schedule ignoring the step; validation scoring `wav` against itself |
| Gate | WER Δ; compute ratio; winner ordering | target-cosine drop 0.05 → 0.5; UTMOS 3.0 → 1.0; `io_floor` dropped; compute dropped from projected T−B; `alg_latency_ms` ignoring lookahead; +12 st tolerance 0.06 → 0.6; tracker built without lookahead; pitch shift not applied in conversion |

One more (FM `detach` removed) is equivalent in the forward value and not
counted as a gap. The speaker-identity rows matter most: nothing in the suite
proves that the speaker embedding reaches the audio (FiLM bypass survives), or
that `voices.json` row *i* is speaker *i*'s embedding — the file Stage 06 ships
and Stage 09 blends.

**F-2 · Training segment is shorter than the receptive field (Medium, design risk).**
Segments are 26 frames = 520 ms; the generator reaches 606 ms into the past, so
**no training sample ever has a full receptive field** — every one starts from
zero-padded context, while at run time the model sees continuous history. HiFi-GAN
non-causal models tolerate this; a causal stack of ~100 convolutions with
dilations up to 5 and 11-tap kernels is more exposed (possible symptom: a click
or level change a few hundred ms into each utterance that short-segment
validation never shows). This is a prediction from the numbers, not something I
observed. The memory headroom is large
(1.74 of 8 GiB). Either raise the segment to ≥ 0.8 s (≥ 13 000 samples) and
re-measure it/s, or discard the loss over the first ~600 ms of each crop.

**F-3 · Validation subset is not speaker-stratified (Low–medium).**
`validate()` scores `items[:limit]`, the first 50 joined rows, and picks
`best.pt` on that. Rows keep the order of the (repeatable) `--val-manifest`
files, each of which is written dataset by dataset, so with LJSpeech first the
best checkpoint is chosen on one voice (read from code; not run on real data). Use `evallist.evenly_spaced` over all
speakers, and log per-speaker mel L1. `best.pt` is what the Stage 06 examples
export.

**F-4 · Invalid speaker names fail at the first checkpoint, not at start (Low).**
`join_vocoder_items` lowercases the manifest speaker but does not check it
against the `voices.json` rule `[a-z0-9_-]+`. Reproduced: `"cori samuel"` and
`"john.doe"` raise `ContractError` from `voices_json`, i.e. from
`save_checkpoint` after ~12–30 minutes of training. Validate once in `train()`
before the loop.

**F-5 · No non-finite guard in the training loop (Low).**
A NaN loss clips to NaN gradients and NaN weights; the run continues until the
next checkpoint, where `voices_json` fails with the misleading
`embedding must be a list of numbers`. Check `torch.isfinite(loss_g)` /
`gnorm`, skip the step, and abort with a clear message after N in a row.

**F-6 · Train/run-time feature mismatch (Low, document it).**
(a) Training features come from `PitchConfig()` (L = 0, past window); student-L1/L2
at run time use the centred window (Stage 03). (b) Each crop warms the tracker
for 400 ms, but the EMA time constant is 4 s, so the "held" log-f0 in unvoiced
stretches relaxes towards the global prior (5.03) in training, towards the
*target speaker's* mean at run time (z → 0 maps to μ_tgt). Both are small
effects on frames the vocoder should already discount by voicing, but they are
exactly the kind of drift the controls checks will measure; note them in
Stage 05 and prefer training-time features with the same `lookahead_frames` as
the chosen head after the gate.

**F-7 · The converted utterance is not flushed (Low).**
`convert_utterance_streaming` feeds exactly the padded input, so with head L the
last L·20 ms of the source are never converted (output frame t carries source
frame t−L). `best_lag` hides the shift for F0-PCC, but WER on tightly cut
LibriSpeech tails is slightly biased against L1/L2 — the candidates the gate
is trying to compare fairly. Push L extra zero hops and drop the first L output
hops.

**F-8 · Smaller items.**
`sample_rate=enc_m.cfg.vocab and ce.SAMPLE_RATE` (`gate_report.py:205`) is a
typo-shaped expression (evaluates to `SAMPLE_RATE` only because `vocab` is truthy);
`DEFAULT_CANDIDATES` has four rows while the task text says "frames_per_step
1/2/4"; `export_smoke_test` and `convert_*` mutate the passed-in models with
`.eval().float().cpu()`; `UnitVocoder.from_checkpoint` raises `TypeError` (not
`ValueError`) on an unknown config key, which `train_unit_vocoder.main` does not
catch; the fine-tune path does not seed RNG (resume does); the post-gate
fine-tune restarts at the full 2e-4 learning rate; the Stage 05 tests have no CI
coverage (the new `python-m2-contract` job installs only the ONNX subset, so
torch-based tests, Stage 03–06 included, run only where the venv exists).
