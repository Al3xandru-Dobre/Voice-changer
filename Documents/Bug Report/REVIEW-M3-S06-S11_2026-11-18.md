## 2. Findings

1. **Stage 06 is not implemented, and it blocks every real-bundle criterion.**
   `fvml/translator.py:891-893` still says "Stage 05 has no prosody head yet"
   and only keeps `prosody_ctx` alive in the graph. `fvml/contract.py:29-31`
   sets `ROLES = ROLES_V1`, so `export_stateful_onnx.py --role` (line 77)
   cannot export `translator_enc` / `translator_dec`. Prosody losses, the 65 s
   multi-utterance parity mode, `langs.json` / `MODEL_CARD.md` writing and the
   bundle-level `validate_s2ut_bundle` call are absent **(audit)**.
2. **Mode B onset is not one number.** The first write happens when the k-th
   speech chunk closes, so onset delay depends on where the utterance starts
   inside an 80 ms chunk: it spans `((k−1)×80, k×80]` ms plus I/O. The master
   budget's `k × 80` is the worst case; the median is about 40 ms lower. The
   Stage 11 DoD "within ±15 ms of the master budget formula" needs to say which
   statistic it compares (p95 or max).
3. **Stage 08's fixture DoD looks one hop too high.** It expects "Mode A
   identity T−B + 3 × 80 ms". Identity s4 already contains the 80 ms hop, so
   the offline numbers above imply identity + `(k−1) × 80` at most. Not
   confirmed live.
4. **The fixture bundle is silent when the target language is `en`.** The
   fixture decoder emits `(prev_units + tgt_lang) mod 16`, starting from BOS =
   16, and `en` is id 0, so every unit is 0 and the fixture vocoder outputs
   zeros. The Stage 08 DoD command (`--src-lang es --tgt-lang en`) therefore
   cannot be measured; use `--tgt-lang de`. Derived from the fixture generator;
   the `es → en` run itself was not made.
5. **Stage 10's tests are not in the gate.**
   `python_training/tests/test_cross_lingual_voice.py` is registered neither in
   `CMakeLists.txt` nor in `.github/workflows/build.yml`. CI also skips
   `test_translator*`, `test_train_s2ut`, `test_s2ut_golden` and `test_export`
   **(audit)**.
6. **The synthetic phrase may not drive a trained translator.** It is vowels,
   not language; a real model may answer with `<EOS>`. If so the latency matrix
   needs a recorded phrase, which `fv_probe` cannot play yet.
7. **Stage files lag the tree.** Stage 06 and 10 say "☐ not started"; Stage 10
   tooling exists (`--freeze-unit-emb-after`, `eval_cross_lingual_voice.py`,
   `prepare_live_mic_set.py`). `Documents/README.md` lists M3 as "Planned", and
   `Milestone 4/07_mode_b_translation_wiring.md` says M3 is not started
   **(audit)**. Root `README.md` has no `--s2ut` / `fv_s2ut_file` quick start
   and no dataset attributions; `RESEARCH_GUIDE.md` has no pointer to the M3
   research report **(audit)**.
8. **Spec deviations in stages 07–09 worth a decision (audit):** `lang <src>
   <tgt>` also resets `wait_k` to the pair default; `fv_s2ut_file` pads
   `400 + (32 + k + 2) × 80` ms of tail instead of the specified 600 ms; the
   1 MB RSS bound is asserted over `OrtModel` steps, not over
   `fv_s2ut_file --repeat 50`; `fluxvoice` has no `--adaptive` flag.
