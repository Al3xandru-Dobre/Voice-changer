## 3. Verified by inspection

- **State naming & order.** Encoder graphs keep exactly `trunk.*` +
  `heads.<H>.*` convs with context > 0 (head 0's k=1 conv correctly drops
  out); vocoder graphs keep the model's full `state_layout()`. `StepGraph`
  input/output orders are the contract's + registration-order states, and
  `export_role` asserts graph states == contract states.
- **Contract v1 orthogonality.** The logits workaround is exactly as
  designed: `logits` exported as a graph output, dropped in `finalize`
  (contract v1 forbids extra outputs), re-added **in memory** by
  `with_outputs` so parity measures \|Δlogit\| on the shipped file. The
  tensor survives in the graph because ArgMax consumes it.
- **ORT 1.31 compatibility caps.** opset ≤ 26 refused above (`MAX_OPSET`),
  IR capped at 13 before checks; `finalize` returns the recorded
  (opset, IR) pair into the report and card.
- **Conditioning = the run-time path.** `conditioning()` pushes the Stage 03
  tracker one cond frame at a time with `lookahead = enc.L ×
  (frame_samples / cond_frame_samples)`, i.e. push *t* returns frame *t−L*,
  matching the delay head's semantics; then `map_to_target` (scale 1,
  shift 0). The ratio arithmetic is right for both the 50 Hz student and a
  12.5 Hz (frame 1280 / cond 320) Mimi-style vocoder, given
  `validate_pair` enforces equal `frame_samples`.
  `test_conditioning_is_the_streaming_tracker_mapped_to_the_voice` pins the
  shift-by-L and the voice-domain mapping numerically.
- **Bundle lifecycle.** Same-checkpoint runs merge variants and (when the
  parity input is unchanged) merge parity/cost; a different checkpoint
  deletes the role's non-re-exported variants and drops `chain`/`chain_cost`
  — **but not `golden/`; that gap is BUG-013**.
- **Gate integration.** `gate_variant()` matches `gate_report.py`'s actual
  JSON (`decision.winner` = candidate name, `candidates[].frames_per_step`,
  top-level `frames_per_step`), verified against `run_gate`'s report
  construction; the exported head's lookahead must equal the winner's
  (`verdicts`), and the model card renders the gate table from the same keys
  the gate rows carry.
- **`voices.json`** is written on *every* vocoder run (not only parity runs)
  and re-validated against the bundle's vocoder contract on every subsequent
  run of either role.
- **Default parity manifest** `manifests/librispeech-dev-clean.jsonl`
  matches `prepare_data.py`'s dataset key (`librispeech-dev-clean`,
  `fvml/datasets.py`), resolved against `$FLUXVOICE_DATA` via `fvml.paths`.
- **CTest wiring.** `python_training_stage06` runs `tests/test_export.py`
  in the pinned venv with `TIMEOUT 600` and `PYTHONIOENCODING=utf-8`
  (the BUG-009 lesson, applied; the cp1252 emoji hazard is also handled by
  `main()`'s `errors="backslashreplace"` reconfigure and `_capture`'s
  stdout swallow).
- **Repo hygiene.** `.gitignore` has `models/*/` (bundles incl. golden) and
  `models/*.onnx`; `models/README.md` matches the implementation (file set,
  state naming, golden layout incl. `cond.npy`, the ≤ 1e-5 audio tolerance,
  and the hop-*t* alignment rule — same wording as the manifest's).
- **No C++ / RT-path changes.** Stage 06 is Python-only; no
  `src/audio`/`src/pipeline` code was touched, so the real-time-callback
  invariants are not at risk from this stage.

## 4. Defects found

| Tag | Defect | Where | Severity |
|---|---|---|---|
| [BUG-013](BUG-013_stale_golden_survives_reexport.md) | *Stale golden* — re-exporting a role from a different checkpoint (especially with `--skip-parity`) deletes the role's old variants and the chain results, but leaves `golden/` and `report["golden"]` untouched: the manifest still references deleted `encoder_sN.onnx` files and carries sha256s of the *old* model. Stage 07's `fv_vc_file`-vs-golden check would then compare the C++ run of the new model against references from the old one — silently, because the shas in the manifest no longer match the files. This contradicts the stage's own design decision "the bundle never mixes models". | `run()` different-model branch + `write_golden` only under `not skip_parity` | Medium |
| [BUG-014](BUG-014_export_cli_traceback_exits.md) | *Traceback exits* — `main()` catches only `(ExportError, ContractError, FileNotFoundError)`. A missing/corrupt parity audio file (`soundfile.LibsndfileError`), a corrupt checkpoint or `export_report.json`, or ONNX Runtime refusing an exported graph (all `RuntimeError` subclasses / `ValueError`s from outside) escape as tracebacks with exit code 1 — which the documented contract reserves for "a gate failed". Same defect shape as BUG-004 was for `contract.py`. | `main()` exception boundary | Low–medium |

Neither defect affects the exported graphs themselves: every file that
reaches the bundle passed the checker, the contract round-trip and pair
validation before the faulty bookkeeping around it.

## 5. Test gaps (no bugs filed)

- **No regression covers BUG-013**: `test_cli_builds_a_bundle` performs the
  different-checkpoint `--skip-parity` re-export but stops asserting at
  `encoder_s2.onnx` disappearing; it never looks at `golden/manifest.json`
  afterwards.
- **No regression covers BUG-014**: no test drives the CLI at a
  missing parity file or a corrupt report and asserts exit 2 with the
  `[export] error:` line.
- `--gate-report` is exercised only through the pure functions
  (`gate_variant`/`verdicts`); the `run()` path that loads the JSON file is
  untested (a malformed gate JSON raises `json.JSONDecodeError`, uncaught —
  same boundary as BUG-014).
- `finalize`'s metadata handling (`_set_meta` replace-vs-append) is unpinned;
  the sorted-metadata-keys property is pinned only for the contract key.
- No test gives `--cost-steps` a hop budget that makes `step_cost` raise
  through the CLI (the raise is pinned only directly).
- Cosmetic: `step_cost`'s error text says "needs more than {warmup} warm-up
  hops" when the true requirement is warm-up + 1 hops total.

## 6. Suggestions

**Do first**

1. Fix [BUG-013](BUG-013_stale_golden_survives_reexport.md): in the
   different-model branch also delete `golden/` and `report.pop("golden")`;
   when regenerating golden, remove per-variant files
   (`units_s*.npy`, `audio_s*.wav`) not in the new variant set; extend the
   CLI test to assert the manifest never references a non-existent file or a
   stale sha.
2. Fix [BUG-014](BUG-014_export_cli_traceback_exits.md) the way BUG-004 was
   fixed for `contract.py`: wrap the external boundaries
   (`audio.load`, `torch.load`, `ort.InferenceSession`, `json.loads` of
   report/gate) so `main()` can classify everything that is not a gate
   failure as exit 2 with one `[export] error:` line.

**Soon**

3. `--skip-parity` re-exports currently *discard* the previous run's
   parity/cost entries for variants whose files survive the merge (the role
   dict is rebuilt without them). Either preserve them for unchanged
   variants or log explicitly that prior parity evidence was dropped; today
   the model card silently flips to "not run".
4. `UnitVocoder.voices_json` defaults a speaker without metadata to
   `license: "unknown"`, which passes `validate_voices` (any non-empty
   string). The stage wants licence + attribution per entry; refuse or at
   least warn, so a fine-tuned bundle cannot ship with placeholder licences.

**Later / hardening**

5. `next(bundle.glob("vocoder_s*.onnx"))` (in `run()`) has no default; a
   bundle with `voices.json` but no vocoder file (manual deletion) turns
   that into an uncaught `StopIteration`. Same for `load_report` on a
   corrupt or wrong-schema `export_report.json` (`JSONDecodeError`).
6. A mutation pass over `fvml/export.py` in the style of the S01–S02 review
   would be cheap insurance for Stage 07: candidates include dropping the
   state feed-back in `OrtStream.step` (pinned only indirectly through
   parity), `MIN_UNIT_AGREEMENT`/`MIN_VOCODER_SNR_DB` boundaries (`>=` vs
   `>`), and the `same_source` key set.
7. Cost numbers include Python dispatch overhead (documented in
   `step_cost`); fine for the relative gate, but Stage 07 should re-measure
   in C++ before drawing conclusions about the s1 54 % miss recorded in the
   stage file.
