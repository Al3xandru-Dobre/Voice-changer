## 3. Test gaps found by mutation testing

The QA rule is "pin each business rule with a test that fails if that rule is
broken". To check, I copied `contract.py` and its tests to a temp tree and broke
one rule at a time (98 mutant definitions, 95 applied after rewriting three
patterns, run against the full pytest suite). **65 were killed, 30 survived.**
Nine of the survivors are *masked or equivalent*: `from_dict` and
`validate()`/`_check_types` both check version, role, content kind, int range and
string types, so removing either copy is invisible. That is redundancy, not a
gap. The other 21 survivors reduce to nine real gaps:

| # | Unpinned rule | Mutant that survives |
|---|---|---|
| 1 | `overlap_samples == hop` is the boundary | `>` → `>=` |
| 2 | a state named `state_out.x` is rejected | only the `state_in.` prefix is tested |
| 3 | `state_out.X` without `state_in.X` is "unpaired" | only the reverse is tested |
| 4 | `vocab` on a soft contract (code-built) | the `content_dim`-on-discrete twin is tested |
| 5 | `to_json()` validates first (docstring says so) | removing `self.validate()` passes |
| 6 | `embed()` replaces a stale contract and sorts other keys | fixtures are embedded into models with no prior key |
| 7 | `f16` state dtype via a real graph (`_value_spec`) | no f16 graph in any test |
| 8 | zero-size state dimension (`d >= 1`) | `>= 0` passes |
| 9 | `validate_voices`: 12 rules | unknown top-level key; missing voice key; **uppercase name** (the test's `"LJ Speech"` fails on the space, so case is never reached); non-ASCII name; `energy_std == 0`; non-number `logf0_mean` / `energy_mean`; non-number embedding element; non-string `display`/`license`/`source`; non-string `attribution`; NaN; non-object voice |

Items 1–4 and 9 need one small case each in `tests/data/contracts/` (1–3) or in
`test_voices_validation` (9). The C++ twin runs the same JSON, so it inherits
every gap; I did not mutation-test the C++ code.

## 4. Python ↔ C++ parity

Read side by side and exercised on the shared cases. Rule order, messages, the
sorted-key unknown-key check, `bool`/`float` rejection and the pair/latency
formulas match. Differences worth knowing:

- Integer literals beyond 64 bits: Python says `out of range`, C++ says `must be
  an integer` (nlohmann parses them as floats). The source comment admits it; no
  shared case pins it.
- Python leaks non-`ContractError` exceptions ([BUG-004](BUG-004_contract_py_leaks_non_contracterror.md)); the C++ validator never throws.
- Both share [BUG-003](BUG-003_contract_extreme_geometry_accepted.md) and [BUG-007](BUG-007_shapeless_state_passes_as_static.md).
- `validate_voices` is Python-only (Stage 08 adds the C++ reader).

**Later / hardening**

7. **Contract v2 is coming** (Milestone 3 Stage 02: "accepts `contract_version`
   ∈ {1, 2}", v1 stays valid, new `translator` role). Today `CONTRACT_VERSION`,
   `ROLES`, `required_keys`, the strict unknown-key rule and the "this build reads
   version 1" message are all single-version. A small per-version schema table
   now will be cheaper than forking both validators in Milestone 3.
8. Add a `.gitattributes` for `tests/data/fixtures/**/*.onnx binary` and
   `tests/data/**/*.json text eol=lf`. This is hardening, not a defect: in a
   scratch repo with `core.autocrlf=true` (this machine's setting) all 18 `.onnx`
   files survived commit and re-checkout byte-for-byte, but only because each
   happens to contain a NUL byte, which makes Git treat it as binary. The
   generator's `--check` normalises CRLF only for `.json`.
9. `make_fixture_models.py --check` reports stale `.onnx` files but not stale
   `.json` ones (an orphaned `voices.json` would pass). Extend the stale scan to
   everything under the output directory.
10. Byte-identical regeneration holds because `uv.lock` pins `onnx`/`protobuf`;
    an upgrade can change serialisation. Say so in the generator docstring and
    regenerate the manifest hashes in the same commit as any `onnx` bump.
11. When `eval_vc.py` is written, record the sha256 of each downloaded weight
    file (Whisper large-v3, `speechbrain/spkrec-ecapa-voxceleb`, UTMOS22) in the
    summary JSON: `uv.lock` pins code, not weights, and the UTMOS file is already
    cached under `data/`.

**Suggestions still open**

- CI has no `uv sync --frozen` + `pytest` job. The first three M2 tests now run on
  all four CI platforms through `ctest`; `test_fixtures.py` (ONNX Runtime
  bit-exactness) and `python_training_stage01_02` run only where the venv exists.
  The fixing session notes this needs a CUDA-free install path for runners:
  `pyproject.toml` routes `torch`/`torchaudio` to the `cu128` index on Linux and

  A CI job that installs only `onnx`, `onnxruntime`, `numpy` and `pytest` would
  be enough for `test_fixtures.py`.

- No test gives `embed()` a model that already has other metadata keys, so its
  key sorting is unpinned (the one surviving gap mutant).

  which is reasonable.
