of the three stages no earlier review covered: 07 (ONNX Runtime C++ runtime),
08 (real-time Mode A pipeline, committed in `c299e9f`) and 09 (voice controls
and presets, **uncommitted** working-tree work). Defects are filed as

structure follows the real-time rules everywhere it was read. Two defects were
found: the macOS build is broken by a Stage 08 header, and the default latency
target counts model lookahead twice. The ML track has no trained model, so no
acceptance criterion of the milestone is met. Several status lines are a month
out of date.**

## 2. Rules the implementation obeys (checked, OK)

- Warm-up runs before the audio backend exists and before the stream starts
  (`src/main.cpp:551`, `:566`, `:702`).
- The final statistics snapshot is taken before `controller.stop()`.
- The conservation identity includes `prefilled` and `skipped`, with a
  per-stream rebaseline in `ModeAWorker::reset()`.
- The only ONNX Runtime include is in `OrtModel.cpp`, guarded by
  `FLUXVOICE_WITH_ORT`; the version check precedes `Ort::Env` creation.
- IoBinding ping-pong flips parity only on success; any failure resets both
  models.
- No exception escapes `pump()` / `process()` (both `noexcept`). The one
  allocation on the worker is the error-text copy on the failure path.
- One producer for `ParamChannel`: only the control loop pushes and flushes.
  The console reader thread touches only its own queue and the stop flag.
- `logf0_tgt = mu_tgt + scale·sigma_tgt·z + shift_st·ln2/12` is implemented
  exactly; the timbre blend is `(1−α)·e_A + α·e_B`.
- Preset loader: clamp with a warning, unknown keys warn, schema must be the
  integer 1, omitted keys leave values unchanged.
- Spot checks of earlier fixes: BUG-006 (`contract.py`, `VoiceCatalog.hpp`)
  and BUG-009 (`model_contract_py` registered in CTest) are in the code.

| lat-ms-double-hop | `lat_ms` in the `[stats]` line adds `algorithmic_samples()` to `queued`; `queued` already contains the framing hop, so the estimate is one hop too high | Low | yes (`src/main.cpp:239-246`); folded into BUG-026 |
| daz-not-on-worker | With one intra-op thread ONNX Runtime creates no pool and `Run` executes on the FluxVoice worker thread. No first-party code sets flush-to-zero / denormals-are-zero on that thread, while the log prints `denormal_as_zero=1`. Decaying filter states could then cause compute spikes in silence | Medium, **plausible** — depends on ORT internals not checked | no |
| stale-willfail | `vc_file_rejects_no_voice` still passes, but `--voice` became optional in Stage 09; the test passes only because the input file is missing. Every `vc_file_rejects_*` case uses bare `WILL_FAIL`, so any non-zero exit satisfies it | Low | no |

| xfade-per-hop | The speaker-embedding crossfade is evaluated once per hop. With four conditioning frames per hop (s4) a five-frame crossfade collapses to two steps. The Stage 09 box "recomputed per frame" is ticked; the bounded-step test runs only s1 | Low | no |
| change-with-repeat | `fv_vc_file --repeat N --change T:…` uses a cumulative step index and keeps the changed parameters across `reset()`, so the written file has the change from sample 0 | Low | no |
| setparams-reject-silent | `ModeAWorker::pump` discards the result of `set_params()` after `ParamChannel::drain` advanced `applied_generation`. A rejected snapshot is reported as applied. For daz-not-on-worker the check is cheap and should be done before any
conclusion: read the floating-point control word on the worker thread after
the first `Run` (`_mm_getcsr()` on x86-64) in a debug log line. If the bits
are clear, set them once at worker start, next to `WorkerPriority`.

## 4. Milestone 3 work inside Milestone 2 files

The working tree has large uncommitted contract v2 (S2UT) changes in
`src/pipeline/ModelContract.hpp` and `python_training/fvml/contract.py`, with
about thirty new fixtures.

  passed its 21 tests.

  skipped silently.
- Ordering hazard: the fixtures and the header changed before the C++ test
  that handles four-model bundles. Commit them together.

## 5. Test gaps (a mutation would survive)

1. **Console layer** (`src/main.cpp`, about 160 lines inside a lambda in
   `main`): `set` / `get` / `preset` / `save`, the "voice B follows voice A"
   rule and "an unknown preset voice must not half-apply" have no test.
2. **Run-time timbre-blend ramp:** no test changes the blend through
   `set_params`; replacing the ramp with a snap passes.
3. **A failed step resets both models:** the fake counts resets, and nothing
   asserts the count.
4. **End-to-end delay with lookahead > 0** through `ModeAWorker`: only
   lookahead 0 is asserted, which is why BUG-026 is invisible to the suite.
5. **Click bound** for gate-threshold, brightness and limiter-toggle steps,
   and the crossfade step bound for s2 / s4.
6. **`WILL_FAIL` CLI tests** check no reason; `lat_ms` and the `--vc` fields
   of the `[stats]` line are untested.
7. **ORT on Windows and macOS:** no CI job builds with ONNX Runtime.
